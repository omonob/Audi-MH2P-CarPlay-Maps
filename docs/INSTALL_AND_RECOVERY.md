# SD 测试安装与恢复边界

发布版本 `v1.0.0-test.1`（V1 测试版）；内部载荷构建标识保持 `2026.10.24-universal-test.1`。仅首次安装、未实机验证。请勿用于唯一且没有恢复手段的生产设备。

## 安装前

1. 下载同一 V1 测试 Release 的 SD ZIP 和 SHA256 清单，先在电脑核对 SHA256，再解压至一张干净 SD 卡。卡根目录应直接看到 `Data`、`Meta` 和说明文件。
2. 测试机须已具备合法可用的原厂 CarPlay。确认是 MH2P、32 位 ARM、M2P 变体；初始门限使用原包清单参考 MU2678。实际 train、后端接口和版本记录格式尚待实机核实。被拒绝时先取日志，不改门限强刷。
3. 保持车辆停稳并满足原厂更新供电／BEM 条件。此前 `BEM LEVEL 1` 是更新开始前的供电状态问题，不等同于绑定解包 `CODE=13`。
4. 保存本机系统及重要数据的可靠备份；能够通过维护连接恢复。本候选不接受已有安装、旧备份或不完整试验残留，不提供覆盖升级／迁移。

## 更新行为

使用原 MH2P 更新菜单选择 SD。原签名入口会把外置 `Data/AUDIJI` 转交给安装器；新候选不再需要挑战码、绑定密码或原设备身份。

新安装器在写入功能文件前检查平台／版本记录、原入口形态、已安装标记、payload 文件数／大小／POSIX CRC、classpath 结构、备份可读性。下载附件的 SHA256 在电脑端验证；车机上的 POSIX CRC 仅用于介质损坏检测，不是密码学签名或防恶意篡改机制。

本机备份位于 `/mnt/persist_new/carplay/mh2p-universal-test-backup`。新增运行文件只在自有 JAR、库目录、decoder 启动 shim 和 mode 文件中；原厂 decoder 副本属于当前车机，不能当作其他设备的恢复文件。

本轮去掉了旧安装器的网卡／SSH／challenge 关闭循环，不安装工程 challenge／autorunner，不删 SD 的 Data／Meta，不删更新历史，也不修改 navigation 程序或服务管理器。安装器本身不发送重启命令；原厂更新流程自身可能要求重新启动，按其提示操作。

## 结果与错误

| 文件／代码 | 含义 |
| --- | --- |
| `INSTALL.log` | 受限安装步骤、错误与入口恢复情况，不收集设备身份 |
| `ERROR.txt` | 本轮明确的失败代码／原因；失败后停止，不继续反复安装 |
| `Done.txt` | 仅安装脚本完成，仍为 `FUNCTIONAL_VALIDATION=PENDING` |
| 40 | 已有安装／备份／结果文件／残留锁，拒绝覆盖 |
| 41 | 平台、版本记录或文件系统布局不在初始门限 |
| 42 | payload 列表、CRC、长度或所需工具不满足 |
| 43 | HMI classpath 未识别或存在歧义，不自动改写 |
| 44／45 | 备份、写入、发布或只读恢复阶段出错；查日志并处理恢复 |

原签名入口、BEM 或更新框架自身仍可能在安装器之前失败。旧包 `CODE=13` 的实车根因没有被本候选诊断闭合；新候选不用原 VC 解包路径，也不能据此宣称以后绝不会出现安装错误。

## 恢复

普通可捕获安装失败时，脚本尝试把**本次已校验的本机备份**恢复为原 `lsd.sh` 和 `dio_manager`，在日志写 `ENTRYPOINT_ROLLBACK=OK` 或失败状态。新测试文件可能留作离线诊断，但原入口不再引用它们。这个机制没有证明断电过程中完全原子，不能替代完整系统备份。

如日志显示恢复失败、安装中断或断电：先停止更新，保留 SD 及本机备份。接通维护链路，核对同机、当前文件与备份，再由维护者恢复；不要拿别人的备份覆盖，也不要手动删除全部目录或循环重启。后续成功安装后的完整卸载／升级迁移流程仍需实机验证，本候选不自动执行它。

## 安装后最少验证

验证库与 JAR 确实加载、Type111 会话和首帧、原厂地图／手机副屏及 BACK 切换、导航数据和**没有导航小卡片**、来电／前后台／手机重连，再分别记录 USB 和无线结果。每项记录真实日期、train、MU、手机／iOS、地图 App 和日志。不能将 Done、registered 或窗口注册当成可见视频。
