# 源码性质、语言和构建关系

## 可以和不可以声称的内容

`research` 是经过发布范围筛选的研究资料，不是完整 OEM 开发树。Native C 来自二进制反编译，包含推测类型、未知调用约定和分析地址；不能直接编译还原运行库。Native 反汇编与伪代码标为 **BASELINE ANALYSIS ONLY**，运行库的本轮差异以 `validation/NATIVE_PATCHES.json` 为准，不能误认为伪代码已由本轮重新编译。

Java `Source` 是本候选 JAR 重新反编译的结果；没有完整原厂依赖，不能直接宣传为可独立构建的完整原厂源码。实际修改工具 `src/UniversalVariant.java` 是 ASM 转换源代码；旧的无卡片 ASM 工具作为已有改造资料保留，新通用适配不重新加入卡片呈现。

## 本轮 Native 修改审计

输入库必须匹配既有白名单源码资料的完整 SHA256。对各自 `audi_device_binding_authorized` 的 Thumb 入口，只修改为返回 1 的两条指令；原四个 32 字节绑定记录清零。记录区由原静态分析中的 `g_audi_bind_a/b/c/d` 标识定位。修改前检查段范围及该记录区没有重定位项，修改后比较文件总长和所有其他字节。不可将这些偏移用到别的固件库上。

这不是原厂 AirPlay 配对安全的替代实现，不提供原厂授权。完整 OEM 接收／解码／DSI 后端仍由目标原系统提供，其 ABI 和真实输出需要实机验证。

## 重建与可复现性的边界

本地适配沿用交接的既有无卡片明文成果，没有重新从零解密。公开前白名单与内部重建区是两回事；仓库不携带用于原设备恢复／解包的身份输入、挑战或私有种子。

源码研究附件包含真实适配工具、安装源码、当前 JAR／运行库及分析资料。精确的历史原始输入和私有维护工具不随该附件分发；因此它不是宣称人人能从零重编译全部 Native 的完整工具链工程。需要再构建原绑定版时，应在原本地交接工程中操作，不能覆盖冻结基线。
